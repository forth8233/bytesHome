# 情感类控制方案

## 1. 方案概述

情感类控制通过理解用户对室内环境的主观感受，结合上下文信息推断用户真实意图，并给出智能建议。

---

## 2. 上下文信息维度

情感推断依赖以下5个维度的上下文信息：

| 维度 | 数据项 | 数据来源 | 用途 |
|------|--------|---------|------|
| **时间信息** | 当前时段（早晨/上午/中午/下午/傍晚/晚上/深夜） | 系统时间 | 判断用户活动状态 |
| | 星期几 | 系统时间 | 工作日/周末行为差异 |
| | 季节（春夏秋冬） | 系统日期 | 冷热感受的背景判断 |
| | 特殊日期 | 日历 | 节假日、纪念日等 |
| **空间信息** | 用户当前位置（区域） | 语音设备位置/传感器 | 判断当前房间 |
| | 楼层 | 设备配置 | 多楼层场景 |
| | 房间类型 | 设备拓扑 | 客厅/卧室/书房等不同用途 |
| **环境信息** | 当前温度 | 温湿度传感器 | 客观环境数据 |
| | 当前湿度 | 温湿度传感器 | 干燥/潮湿判断 |
| | 光照强度 | 光照传感器 | 明暗客观数据 |
| | 空气质量 | 空气检测器 | PM2.5/VOC等 |
| **设备状态** | 当前运行的设备 | 设备状态查询 | 已开启的设备 |
| | 设备参数 | 设备状态查询 | 空调温度、风速等 |
| | 窗帘状态 | 设备状态查询 | 窗帘开合度 |
| **用户历史** | 最近操作 | 操作日志 | 上下文继承 |
| | 习惯偏好 | 用户画像 | 个性化建议 |
| | 近期行为模式 | 行为分析 | "每天晚上10点关灯"等规律 |

## 3. 主观感受分类

用户对室内环境的主观感受分为以下类别：

| 感受类别 | 主观感受词 | 感受描述 |
|---------|-----------|---------|
| **温度类** | 冷/热 | 对室内温度的直感 |
| | 冻/烫 | 极端温度感受 |
| | 闷 | 温度+通风不良的综合感受 |
| **光线类** | 暗/黑 | 光照不足的感受 |
| | 亮/刺眼 | 光照过强的感受 |
| **湿度类** | 干/干燥 | 空气湿度不足 |
| | 潮/湿/闷 | 空气湿度过高 |
| **空气类** | 闷/不新鲜 | 通风不良/空气质量差 |
| | 臭/异味 | 空气中有异味 |

## 5. 温度感受处理规则

### 5.1 决策规则总览

| 维度 | 决策因子 | 权重 | 规则说明 |
|------|---------|------|---------|
| 时间 | 季节 | 高 | 冬季优先地暖，夏季优先空调 |
| 时间 | 时段 | 中 | 夜间优先静音设备 |
| 环境 | 当前温度 | 高 | 与目标温度差值决定调节幅度 |
| 环境 | 温差变化趋势 | 中 | 升温/降温趋势判断 |
| 设备 | 可用设备类型 | 高 | 空调/地暖/风扇等 |
| 设备 | 设备当前状态 | 中 | 已开启/关闭 |
| 用户 | 历史偏好 | 高 | 用户习惯温度 |
| 用户 | 近期选择 | 中 | 最近3次选择记录 |

### 5.2 规则描述

1. **语义解析**：根据用户表达识别感受类型——"冷/冻/凉"归为"冷"，"热/烫"归为"热"，温度正常但说"闷"归为"闷热"。

2. **计算目标温度**：根据季节和感受类型计算建议温度。
   - **冷+冬季**：当前温度+3°C，下限22°C，上限26°C
   - **冷+夏季**：当前温度+2°C，下限24°C，上限26°C
   - **冷+春秋**：默认25°C
   - **热+夏季**：当前温度-3°C，上限26°C，下限24°C
   - **热+冬季**：当前温度-2°C，上限22°C，下限18°C
   - **热+春秋**：默认24°C
   - **闷热**：温度不变，只调风速或新风

3. **设备选择**（决策优先级：用户历史 > 季节适配 > 静音需求 > 响应速度）：
   - **感到冷时**：
     - 有地暖且为冬季 → 优先选地暖（夜间也优先地暖，因为静音舒适）
     - 无地暖 → 选空调制热模式
     - 无空调 → 选电暖器
   - **感到热时**：
     - 有空调 → 选空调制冷模式（若空调当前为制热模式则自动切换）
     - 无空调 → 选风扇
   - **感到闷时**：
     - 有新风系统 → 打开新风
     - 无新风有排气扇 → 打开排气扇
     - 都没有但空调已开启 → 加大空调风速

4. **生成建议话术**：告知用户当前温度、建议操作及预计生效时间（地暖约30分钟，空调约10分钟）。

### 5.3 边缘程序决策示例

| 用户表达 | 季节 | 时段 | 当前温度 | 可用设备 | 用户历史 | 决策结果 | 系统建议 |
|---------|------|------|---------|---------|---------|---------|---------|
| "有点冷" | 冬季 | 晚上9点 | 20°C | 空调+地暖 | 最近3次选地暖 | 地暖 | "检测到当前温度20度，调高地暖温度至23度，地暖升温较慢但更舒适，预计30分钟后达到目标温度。" |
| "有点冷" | 冬季 | 早上8点 | 18°C | 空调+地暖 | 无历史记录 | 地暖 | "检测到当前温度18度，调高地暖温度至22度（地暖升温较慢但更舒适），预计30分钟后达到目标温度。" |
| "太热了" | 夏季 | 下午3点 | 30°C | 空调+风扇 | 最近3次选空调 | 空调 | "检测到当前温度30度，将空调温度调低到24度，预计10分钟后达到目标温度。" |
| "好闷" | 夏季 | 傍晚6点 | 28°C | 空调+新风 | - | 新风+空调 | "检测到当前温度28度，打开新风系统并将空调温度调低到25度。" |
| "有点冷" | 春季 | 晚上 | 22°C | 只有空调 | - | 空调 | "检测到当前温度22度，打开空调制热模式，设定温度25度，预计10分钟后达到目标温度。" |

## 6. 光线感受处理规则

### 6.1 灯光用途分类

| 用途分类 | 功能描述 | 常见灯具 | 控制优先级 |
|---------|---------|---------|-----------|
| 主照明 | 提供房间基础照明 | 吊灯、吸顶灯、天花灯 | 暗→优先开启 |
| 辅助照明 | 环境氛围或特定任务 | 筒灯、台灯、床头灯、阅读灯 | 按需开启 |
| 装饰照明 | 增加空间美感 | 灯带、线型灯、晴空灯 | 场景联动 |
| 强调照明 | 突出特定物品或区域 | 射灯、轨道灯、洗墙灯 | 手动控制 |
| 背景照明 | 减少屏幕反光 | 背景灯 | 观影场景 |
| 安全照明 | 夜间或紧急情况 | 夜灯、应急灯、地脚灯 | 自动/手动 |

### 6.2 处理流程

```
输入：用户表达光线感受（暗/亮/刺眼）
    ↓
Step 1: 确定用户当前区域和时间
    ↓
Step 2: 获取该区域的光照传感器数据
    ↓
Step 3: 判断光源优先级
    ├─ 时间段：白天 → 优先开窗帘（自然光）
    ├─ 时间段：夜晚 → 直接开灯
    └─ 光照强度：极低 → 灯光+窗帘组合
    ↓
Step 4: 灯光控制策略（按用途分类执行）
    ├─ 用户说"暗"→开启主照明（吊灯/吸顶灯）
    ├─ 用户说"想看书"→开启辅助照明（阅读灯/台灯）
    ├─ 用户说"看电视"→开启背景照明+关闭主照明
    ├─ 用户说"太亮"→调暗主照明或关闭
    └─ 用户说"刺眼"→降低主照明亮度
    ↓
Step 5: 生成建议
```

| 用户表达 | 时间 | 区域 | 当前光照 | 窗帘状态 | 推断意图 | 系统建议 |
|---------|------|------|---------|---------|---------|---------|
| "好暗" | 下午2点 | 客厅 | 低 | 窗帘关闭 | 开窗帘 | "是否打开客厅窗帘？" |
| "好暗" | 晚上9点 | 卧室 | 0 | 窗帘关闭 | 开主照明 | "是否打开卧室吸顶灯？" |

## 7. 空气感受处理规则

### 7.1 处理流程

```
输入：用户表达空气感受（闷/臭/干/潮）
    ↓
Step 1: 获取该区域的空气质量/湿度数据
    ↓
Step 2: 匹配感受与设备能力
    ├─ 闷/不新鲜 → 新风系统 > 排气扇 > 窗户
    ├─ 臭/异味 → 排气扇 > 空气净化器 > 新风
    ├─ 干/干燥 → 加湿器
    └─ 潮/湿 → 除湿器 > 空调除湿模式
    ↓
Step 3: 判断可执行设备
    ├─ 检查该区域是否有新风/排气扇/空气净化器
    ├─ 若多个设备可用 → 进入Step 3.1（多设备选择）
    └─ 若单个设备可用 → 直接选择该设备
    ↓
Step 3.1: 多设备选择
    ├─ 新风 vs 排气扇：新风优先（全屋换气效果更好）
    ├─ 排气扇 vs 空气净化器：根据异味来源选择
    └─ 若无法判断 → 反问用户选择
    ↓
Step 4: 生成建议
```

### 7.2 多设备选择示例

| 场景 | 可用设备 | 系统处理 | 用户回复 | 执行结果 |
|------|---------|---------|---------|---------|
| "好闷" | 新风+排气扇 | "客厅有新风系统和排气扇，您想开启哪个？" | "新风" | 开启新风 |
| "有烟味" | 排气扇+空气净化器 | "可以开启排气扇或空气净化器，您想怎样？" | "排气扇" | 开启排气扇 |

## 8. 综合场景推断

当用户表达多个感受或复杂场景时，进行综合判断：

| 用户表达 | 推断场景 | 综合意图 |
|---------|---------|---------|
| "准备睡觉" | 睡眠模式 | 关灯 + 关窗帘 + 空调睡眠模式 |
| "准备起床" | 起床模式 | 开窗帘 + 灯光渐亮 |
| "我要看书" | 阅读场景 | 灯光调亮 + 色温偏暖 + 窗帘开 |
| "看电视" | 影院场景 | 灯光调暗 + 窗帘关 |

## 10. 习惯学习（v1.x）

| 学习内容 | 数据来源 | 应用场景 |
|---------|---------|---------|
| 温度偏好 | 用户确认执行时的设定值 | 情感推断时作为建议基准 |
| 亮度偏好 | 用户调节灯光时的参数 | "有点暗"时直接建议偏好亮度 |
| 常用区域 | 高频唤醒位置 | 空间推断辅助 |
| 时间规律 | 固定时间的固定操作 | "晚上10点关灯"等规律发现 |
| 季节适应 | 不同季节的调节习惯 | 夏季vs冬季的默认温度差异 |
